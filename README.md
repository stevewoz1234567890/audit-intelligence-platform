# Audit Intelligence — IIA Reference Platform

A static, browser-based reference platform for the **IIA Global Internal Audit Standards**.

It brings together:

- the standards navigator
- detailed standard records
- Domain I guidance
- supporting references
- practical audit tools
- a platform-scoped AI assistant

**Developed by Noora AlZaraa**

---

## Running the project

No installation, package manager, build step, or server is required.

Open `index.html` in any modern browser.

---

## Current pages

| File | Purpose |
|---|---|
| `index.html` | Homepage with hero, search, library entry points, and AI assistant call-to-action |
| `standards.html` | Browse the Global Internal Audit Standards by Domain and Principle, including Domain I |
| `standard.html?ref=<number>` | Standard detail page for a numbered standard such as `1.1` or `13.3` |
| `references.html` | Supporting reference library |
| `tools.html` | Practical audit tools and browser-saved worksheets |
| `assistant.html` | AI assistant that answers only from platform-held content |

```text

  iia.css              shared design system and page styling
  iia.js               shared UI logic, navigation, search, references, tools
  audit-background-2172x724.png    original supplied homepage banner
  standards/           supplied PDFs for Principles 1–15 and Public Sector Application

data/
  iia.js               Domain / Principle / Standard structure, Domain I content
  library.js           detailed standard records
  supplied-standards.js  PDF-backed content for Principles 3–15
```

The shared page scripts load the relevant combination of:

1. `data/library.js`
2. `data/supplied-standards.js`
3. `data/supplied-tables.js` (pages that search or answer from table rows)
4. `data/iia.js` and `data/references.js`
5. `assets/iia.js`

The standard detail page also loads `data/supplied-appendix-tables.js` and `assets/source-format.js` for PDF-backed tables and prose.

Shared chrome such as the header, sidebar, and footer is generated by `mount()`.

## Architecture

This project is currently a **static JavaScript application**, not a framework-based app.

### Characteristics

- plain HTML pages
- plain CSS
- plain JavaScript
- no `package.json`
- no build tooling
- no backend
- no database
- dependency-free browser smoke tests in `tests/` (Chrome remote debugging port 9339)

### Data model approach

- `DOMAINS` in `data/iia.js` defines the standards framework structure
- `DOMAIN_I` in `data/iia.js` defines the dedicated Domain I content experience
- `RECORDS` in `data/library.js` holds detailed standard content
- `SUPPLIED_RECORDS` in `data/supplied-standards.js` holds extracted client-supplied PDF summaries for Standards 3.1–15.2 and takes precedence over older overlapping records
- `assets/source-format.js` formats the supplied prose, bullet points and tabular content using the shared standard-page design. It does not change the underlying PDF wording.
- `data/supplied-tables.js` holds two-column risk, control, and audit-procedure tables reconstructed from the supplied PDFs.
- `data/supplied-appendix-tables.js` holds the eight smaller tables checked against the supplied PDF excerpts, including the Standard 15.2 action-monitoring appendix.
- `REFS` and `TOOLS` are defined in `assets/iia.js`

To regenerate PDF-backed records, run `node tools/import-supplied-standards.cjs <absolute path to the supplied PDFs>` with `pdftotext` on PATH (or set `PDFTOTEXT` to its executable path). `Standared 14.pdf` retains the original source filename; the published asset is `assets/standards/standard-14.pdf`. The PDFs contain summarized guidance and separate suggested practical applications; the platform labels them accordingly rather than presenting them as verbatim IIA publications.

To regenerate the two-column risk, control, and procedure tables after an import, run `node tools/build-supplied-tables.cjs` with Xpdf `pdftotext` available (set `PDFTOTEXT` if it is not in the default location). The smaller, manually reviewed appendix tables in `data/supplied-appendix-tables.js` are not automatically regenerated. Run `node tests/table-reconstruction.cjs`, `node tests/appendix-tables.cjs`, and `node tests/source-format.cjs` to check the imported wording and table content. With Chrome running on remote-debugging port 9339, run `node tests/supplied-standards-smoke.cjs` and `node tests/public-sector-smoke.cjs` to check all 52 standards at desktop/mobile widths and the Public Sector navigation. Automated text checks cannot replace a full editorial review of the source PDFs.

Run `node tests/search-assistant-smoke.cjs` **after**, not concurrently with, the other browser tests: all of them reuse the same Chrome tab. This test checks standard-number and passage search, linked reference items, all 52 assistant requirement/implementation/conformance answers, all 46 imported risk/control/procedure/red-flag answers, the six reference details, the six tool worksheets, Public Sector links, and the unsupported-question fallback. Search indexes platform-held content only. Search results for imported table text link to the relevant section and highlight the matching row; supporting-reference results link to individual items. The assistant is a deterministic, browser-only guide to platform-held content, not a model or an authoritative reproduction of IIA requirements; supplied PDFs are summaries, and generated practical checklists are not conformance evidence.

The supplied archive also includes Standards 1 and 2 and Public Sector PDFs; they are linked from the corresponding pages. The first six standards retain their existing structured records. To compare those records with the supplied PDFs without rewriting them, extract `standard-1.pdf` and `standard-2.pdf` to a temporary directory, run `pdftotext -layout -enc UTF-8` on each to create `Standard 1.txt` and `Standard 2.txt`, then run `node tests/early-source-audit.cjs <absolute temporary directory>`. Reported differences can reflect UK/US spelling; review the source rather than automatically overwriting the records. The Public Sector application content is paraphrased, while suggested audit material is separately labelled.

PDF editorial checks: `node tests/pdf-render-audit.cjs` compares all 461 rendered PDF-backed fields with the imported words; `node tests/pdf-row-audit.cjs` independently extracts the 13 linked PDFs with `pdftotext -table` and compares all 889 rows with their ordered PDF line spans, including cell-pair anchors. The row audit requires Xpdf's `pdftotext` (or `PDFTOTEXT` set to its executable path). To verify the stored source text against a fresh extraction without overwriting it, set `AUDIT_IMPORT_OUTPUT` to a temporary output file and run `node tools/import-supplied-standards.cjs <absolute path to assets/standards>` with `PDFTOTEXT` set. In this audit-only mode the importer reads the published lowercase `standard-N.pdf` filenames, including `standard-14.pdf`. Review the resulting file against `data/supplied-standards.js`. These checks do not prove the accuracy of the client-authored PDF against the official IIA publication, and desktop/mobile screenshot inspection remains a separate step.

## Search and assistant scope

Both search and the assistant operate **only on content held inside this platform**.

### Search

Search is local and browser-side.

It currently searches:

- numbered standards
- Domain I content
- supporting references
- audit tools

There is **no internet search** and no external index.

### AI assistant

The AI assistant is a **platform-scoped retrieval and response layer**.

It does not browse the internet and does not answer from general knowledge when the platform lacks the content.

It can currently answer from:

- detailed standards loaded in the platform
- Domain I
- supporting references
- audit tools

Where platform content is insufficient, it declines rather than inventing content.

## Notes on content handling

This platform distinguishes between:

- **official-source material**, which remains with the issuing body
- **platform-authored practical guidance**, which is structured for auditor use

The interface links to official sources where appropriate.
